# 禅道 Token 自动登录与持久化设计

## 目标

让 MCP 在 `ZENTAO_TOKEN` 缺失或失效时，使用本机 `.env` 中配置的专用禅道账号自动登录，取得新 Token，将其安全写回 `.env`，并继续完成原始只读查询。账号、密码和 Token 不得出现在 MCP 工具参数、正常返回或错误消息中。

## 范围

本次包含：

- 检测 Token 是否缺失。
- 在禅道 API 返回 HTTP 401 时判定 Token 失效。
- 使用 `ZENTAO_ACCOUNT` 和 `ZENTAO_PASSWORD` 调用 `POST /tokens`。
- 在进程内缓存新 Token，并将其写回当前项目的 `.env`。
- 自动重试一次因认证失败的原始 GET 请求。
- 更新配置示例、使用文档和自动化测试。

本次不包含：

- 创建、修改或删除禅道业务数据。
- 让模型读取、提交或传递账号密码。
- 图形化登录、验证码、单点登录或多账号切换。
- 定时刷新 Token，或在非 401 错误时反复登录。

## 配置约定

`.env` 支持以下字段：

```dotenv
ZENTAO_BASE_URL=http://10.10.11.204
ZENTAO_API_PREFIX=/api.php/v1
ZENTAO_TOKEN=
ZENTAO_ACCOUNT=codex-bot
ZENTAO_PASSWORD=机器人账号密码
ZENTAO_TIMEOUT_MS=15000
```

- `ZENTAO_BASE_URL` 仍为必填。
- `ZENTAO_TOKEN` 改为可选；有值时优先使用。
- `ZENTAO_ACCOUNT` 和 `ZENTAO_PASSWORD` 仅在需要登录时校验。这样，有效 Token 用户无需额外配置密码。
- 项目使用 `dotenv` 由 Node.js 直接读取 `.env`，避免启动脚本用 shell `source` 解析密码中的空格、`#`、`$` 等字符。
- 启动脚本只负责定位并启动 `server.mjs`；`.env` 的缺失和字段校验由 Node.js 返回明确错误。

## 组件边界

### `lib/env-file.mjs`

只负责 `.env` 文件持久化：更新或追加 `ZENTAO_TOKEN`，保留其他行、注释和换行风格；不负责网络请求或认证决策。

写入流程：

1. 读取当前 `.env`。
2. 替换第一个有效的 `ZENTAO_TOKEN=` 配置行；不存在时在文件末尾追加。
3. 在同目录创建仅当前用户可读写的临时文件。
4. 写入完整内容并设置权限为 `0600`。
5. 使用原子重命名替换 `.env`，最终再次确保权限为 `0600`。
6. 无论成功或失败都清理遗留临时文件。

Token 值按 dotenv 双引号格式序列化，并转义反斜杠、双引号、换行和回车，确保重新加载后值不变。

### `lib/zentao-client.mjs`

只负责 HTTP、Token 生命周期和认证重试，对外暴露 `get(path, query)`。它接收基础 URL、API 前缀、初始 Token、账号密码、超时、`.env` 路径和可注入的 `fetch`/持久化函数，以便独立测试。

内部维护：

- 当前内存 Token。
- 一个可选的 `refreshPromise`，用于合并并发刷新请求。
- 不包含密码或 Token 的错误包装逻辑。

### `server.mjs`

继续负责 MCP 工具注册、输入校验和禅道数据裁剪。它加载 `.env`、创建一个禅道客户端，并将现有 `zentaoGet` 调用改为客户端的 `get`。工具名称、参数和正常返回结构保持不变。

## 请求和刷新流程

1. MCP 工具调用客户端 `get`。
2. 如果内存中没有 Token，客户端先进入刷新流程。
3. 刷新流程检查账号和密码；缺失时抛出不包含敏感值的配置错误。
4. 客户端向 `${baseUrl}${apiPrefix}/tokens` 发送 JSON：`{"account": ..., "password": ...}`。
5. 登录成功后，从响应顶层 `token` 字段读取非空字符串。
6. 先将新 Token 写回 `.env`；写入成功后更新内存 Token。
7. 使用新 Token 发出原始 GET 请求。
8. 如果带 Token 的 GET 返回 401，刷新一次并重试原始请求一次。
9. 重试仍返回 401 时直接报错，不进行第三次登录或请求。

Token 有值时不额外调用验证接口；真实业务请求本身就是有效性检查，避免每次工具调用增加一次网络往返。

## 并发行为

当多个查询同时发现 Token 缺失或收到 401 时，第一个查询创建 `refreshPromise`，其余查询等待同一个 Promise。刷新完成后清空该引用。这样一轮失效最多产生一次登录请求和一次 `.env` 写入。

如果某个请求收到 401，但发现内存 Token 已被其他请求刷新，则它直接用较新的 Token 重试，不再次登录。客户端通过比较该请求使用的 Token 和当前内存 Token 判断这一情况。

## 错误处理与安全

- 登录接口的非成功状态统一报告为“禅道自动登录失败”并包含 HTTP 状态码；不得拼接原始请求体、密码或 Token。
- 登录响应不是 JSON 或缺少非空 `token` 时，返回明确的响应格式错误。
- GET 的 401 进入一次刷新；403、404、429、5xx 和网络错误不触发登录。
- 超时继续使用 `AbortController`，登录和查询共用 `ZENTAO_TIMEOUT_MS`。
- `.env` 写入失败时不更新内存 Token，也不继续原始请求，避免运行状态与磁盘配置不一致。
- `.env` 必须保持 `0600`；`.gitignore` 继续忽略它。
- MCP 工具定义保持只读注解；自动更新本机认证配置不改变禅道业务数据。

## 测试策略

使用 Node.js 内置 `node:test`，不引入测试框架。网络测试注入受控的 `fetch` 实现，文件测试使用临时目录中的真实文件。

覆盖以下行为：

- 有效初始 Token：直接查询，不调用登录。
- Token 缺失：登录、持久化，然后查询。
- 首次 GET 返回 401：刷新 Token，并使用新 Token 重试一次。
- 多个并发请求共享一次刷新。
- 登录重试仍为 401 时停止，不无限刷新。
- 账号或密码缺失时给出安全的配置错误。
- 登录失败及格式错误不泄露敏感内容。
- `.env` 中已有 Token 时只替换对应值，并保留其他配置和注释。
- `.env` 中没有 Token 时追加配置。
- 持久化后的 `.env` 权限为 `0600`。

`package.json` 增加 `test` 脚本，并让 `check` 检查所有生产模块的语法。最终验证运行 `npm test` 和 `npm run check`。

## 成功标准

- 有效 Token 的现有调用行为不变。
- Token 缺失或返回 401 时，配置了正确账号密码即可无人工介入地完成原查询。
- 获取的新 Token 自动写回 `.env`，且文件权限为 `0600`。
- 一次请求最多自动刷新一次；并发刷新不会重复登录。
- 所有认证信息均不通过 MCP 上下文暴露给 AI。
- 自动化测试与语法检查全部通过。
