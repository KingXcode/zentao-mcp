# 禅道 MCP 停止脚本设计

## 目标

在项目根目录提供可直接执行的 `stop.sh`，一次停止由本项目 `start.sh` 启动的全部禅道 MCP Server 实例，同时不影响其他项目或其他 Node.js 进程。

## 用户流程

停止全部实例：

```bash
cd /Users/nsy/DevProjects/zentao-mcp
./stop.sh
```

重启：

```bash
./stop.sh
./start.sh
```

如果当前没有本项目实例，脚本显示“禅道 MCP 未运行。”并以状态 0 退出，便于重复执行。

## 进程识别

`start.sh` 最终使用：

```sh
exec node "$SCRIPT_DIR/server.mjs"
```

因此 `stop.sh` 根据自身位置计算本项目 `server.mjs` 的绝对路径，将该路径转义为安全的扩展正则表达式，再使用系统 `/usr/bin/pgrep -f` 匹配命令行以 `node <本项目绝对路径/server.mjs>` 结束的进程。

匹配约束：

- 项目路径必须来自 `stop.sh` 自身目录，不接受命令行路径参数。
- 正则对路径中的空格和元字符进行转义。
- 模式锚定命令行末尾，避免匹配测试命令、编辑器或包含相同文字的其他参数。
- 使用 `[n]ode` 形式避免进程查找命令匹配自身。
- 只处理 `pgrep` 返回的数字 PID。

## 停止语义

- 对所有匹配 PID 发送 `TERM`，让 Node.js 进程优雅退出。
- 不发送 `KILL`，不强制终止无法响应 `TERM` 的进程。
- 进程可能在查找和发送信号之间自行退出；这种竞态不会使脚本失败。
- 找到实例时输出目标数量和停止结果，不输出 `.env`、Token、账号或密码。
- `pgrep` 不可用或发生非“没有匹配”的查找错误时，返回非零状态和固定错误，不尝试扩大匹配范围。

## 测试策略

自动化测试使用临时目录：

1. 将 `stop.sh` 复制到临时项目目录。
2. 创建临时 `server.mjs`，启动两个长驻 Node.js 子进程。
3. 同时启动一个路径不同的 Node.js 长驻进程作为非目标。
4. 执行临时目录中的 `stop.sh`。
5. 断言两个目标进程收到 `TERM` 并退出，非目标进程仍在运行。
6. 再次执行脚本，断言显示“未运行”且状态为 0。

测试只终止临时目录中由测试创建的进程，不匹配或停止真实项目 MCP。若沙箱禁止进程枚举，测试按批准流程在沙箱外执行，不降低匹配约束。

## 成功标准

- `./stop.sh` 能停止本项目全部 MCP 实例。
- 不会停止其他 Node.js 进程。
- 没有运行实例时可安全重复执行。
- 项目路径包含空格时仍可工作。
- 脚本通过 `sh -n`、行为测试、全量测试和 `git diff --check`。
